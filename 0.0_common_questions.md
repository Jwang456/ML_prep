### Q4. Can you explain the differences between bagging and boosting in ensemble learning?

**1. Bagging**

- Train multiple models in PARALLEL on different bootstrap samples
- Each model sees different data subsets (sampling WITH replacement)
- Aggregation: Average predictions (regression) or majority vote (classification)
- Reduce VARIANCE - prevents overfitting by averaging out individual model errors

**2. Boosting**

- Train models SEQUENTIALLY, where each model corrects previous models' mistakes (Remaining Gradient)
- Each new model focuses on examples the previous models got wrong
- aggregate by starting with initial forecast and sequentially 
adding each weak learner's contribution using the learning rate
- Reduce BIAS - converts weak learners into strong learners

When our base model is prone to overfitting, we can use bagging to reduce the variance to increase the generalization ability and for boosting, if our model is underfitting, we can using boosting to ensemble our weak learners to a powerful learner. 

For example, Random Forest uses bagging with decision trees to prevent 
overfitting, while XGBoost uses boosting to turn shallow trees (weak learners)
into a powerful ensemble.

### Q7. Why does a CTR (Click-Through Rate) prediction model need calibration?

CTR prediction models need calibration because there's a critical difference between ranking performance and probability accuracy.

**The Core Problem:**

- Models are trained to optimize ranking metrics (AUC, ranking loss)
- But business needs actual probability estimates for bid optimization and ROI calculation
- A model might perfectly rank ads by likelihood to be clicked, but predict 5% when actual CTR is 1%

**Technical Reasons for Miscalibration:**

1. **Optimization mismatch**: Cross-entropy loss optimizes for discrimination, not calibration
2. **Class imbalance**: CTR datasets are heavily imbalanced (typically <1% positive)

**Business Impact:**
- **Advertiser trust**: Predicted 5% CTR sets ROI expectations, actual 1% kills campaigns
- **Bid optimization**: Advertisers set bids based on predicted probabilities

**Calibration Methods:**

- **Platt scaling**: Fit sigmoid to model outputs on validation set
- **Isotonic regression**: Non-parametric monotonic mapping
- **Temperature scaling**: Single parameter to adjust confidence

## Bias-variance tradeoff

The bias-variance tradeoff is one of the fundamental concepts in machine learning that helps us understand model performance and generalization

Bias refers to the error introduced by approximating a real-world problem with a simplified model. High bias means the model makes strong assumptions about the data and consistently misses relevant patterns - it's systematically wrong. For example, trying to fit a linear model to inherently non-linear data creates high bias. This leads to underfitting.
- how far off the model's average prediction is from the true value

Variance refers to the model's sensitivity to small fluctuations in the training data. High variance means the model captures noise and random patterns that don't generalize to new data. For instance, a decision tree with no depth limit might perfectly memorize training data but fail on test data. This leads to overfitting.

The tradeoff exists because these two sources of error are inversely related:

- Simple models (like linear regression) typically have high bias but low variance
- Complex models (like deep neural networks) typically have low bias but high variance

Total Error = Bias² + Variance + Irreducible Error

Optimize the tradeoff by

- Model selection: Choose complexity appropriate for the data - use cross-validation to find the sweet spot where total error is minimized
- Regularization: Add penalties (L1/L2) to constrain model complexity, reducing variance at the cost of slightly higher bias
- More data: Generally reduces variance without affecting bias, which is why it's often the best solution when feasible
